# 简历项目经历

**证据驱动的技术选型研究 Agent｜Python、LangGraph、DeepSeek／Qwen 兼容接口、Tavily、FastAPI、SQLite、Gradio**

- 面向开发者技术选型，构建支持需求澄清、并行资料研究、证据核验与报告修订的Agent工作台，覆盖向量数据库、搜索API和知识库平台三组产品。
- 通过原生工具调用完成搜索与公开页面读取，保存原文快照、段落引用和版本信息；结合程序校验与模型语义判断区分支持、冲突和证据不足，仅对缺口进行有预算的定向补查。
- 将产品事实与条件式推荐分离，用户修改条件后复用同一会话内仍有效的证据，重新生成判断并展示版本差异；通过SQLite保存任务、证据与不可变报告版本，支持中断记录、取消和历史导出。
- 建立真实HTTP闭环测试、确定性场景验收及受控消融，分别记录引用门禁、报告修订、调用次数和实际耗时，保留真实模型运行失败案例与原始轨迹。

## 面试可展开的实现问题

1. 为什么来源可访问、词项重合仍不能证明结论受支持？程序门禁与模型核验各自保证什么？
2. 同一功能在不同版本、地区或套餐中的描述不一致，怎样区别冲突和条件差异？
3. 为什么为Researcher预留提交结果和修正格式的预算？真实模型持续搜索会产生什么后果？
4. 修改用户条件时，为什么不能把先前推荐直接当成产品事实复用？
5. 价格与普通技术文档为什么使用不同TTL？旧报告如何保留当时依据？
6. 额度耗尽、网页打不开和任务取消时，哪些成果能保留，哪些不能声称完成？

以上为实现描述，不包含未测量的效果数字。真实模型覆盖范围与结果应按最终`reports/VALIDATION.md`补充；fixture通过率不能写成真实模型准确率。没有真实企业上线、完整产品性能基准或人工事实正确率的声明。
