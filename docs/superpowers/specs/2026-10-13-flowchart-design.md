# 选型结果流程图设计

## 目标

用户确认技术选型结果后，系统生成一份可审查、可学习、可追溯的项目流程图。流程图必须来自已保存的任务状态和报告数据，不能由图像模型自行推断流程关系。

## 范围

首版提供确定性 Mermaid 图和结构化 JSON。图覆盖条件澄清、并行研究、证据核验、预算允许时的补查、推荐依据核验和报告版本；节点状态可表示完成、部分完成、失败和等待输入。首版不调用 ComfyUI 或付费图像 API。

视觉生成作为后续适配器：如果启用，输出仅为展示附件，不能替代 Mermaid 或 JSON，也不能改变节点、边、状态或证据关系。

## 已确认的用户项目流程（主要交付）

研究过程图为辅助图。主要流程是：目标与约束 → 提出最多 6 层、每层最多 3 个技术候选 → 追问并修订目标或允许未知 → 对指定层按既有证据流程研究 → 用户确认各层产品及拟议连线 → 保存不可变项目架构版本 → Mermaid/SVG 审查和学习。

首版项目选项使用已有固定候选目录，或用户提供的自定义目录；不会把固定目录包装成已针对任意目标自动发现的技术。候选理由明确为设计假设，尚未经公开资料核验。公开资料研究复用现有图、预算及门禁，并用自定义目录限制产品和维度。每层研究由用户显式启动；不自动批量消耗 6 层研究预算。fixture 候选为标注的合成教学样例，不按任意目标声称真实适配性。后续如接入模型提出候选，必须增加候选生成 Schema、去重、范围确认和独立证据核验。

确认架构时必须引用该项目该层的已发布报告版本，并从该报告候选中选择产品。拟议架构边是用户认可的设计关系，不是产品集成兼容性实测。未知能力与缺口原样保留。架构版本绑定目标、层次、选择、报告版本、证据引用和连线；旧版不受后续报告变化影响。

本轮实现内置确定性 SVG，以便工作台直接显示图形和下载；图片生成不参与组件或连线决策。

## 数据与边界

流程图构建器消费任务的 `trace`、`brief`、`claims`、报告状态和报告版本，输出 `FlowGraph`。节点包含稳定 id、标题、类型、状态、产品和可选引用；边包含稳定 id、起点、终点、标签。没有实际记录的步骤只能以“未执行”状态出现，不能假定成功。

渲染器只负责将 `FlowGraph` 转成 Mermaid 文本；API 和 UI 负责读取已有任务或报告。生成图不触发研究、搜索、模型调用或文件读取。

## API 与展示

- `GET /v1/tasks/{task_id}/flowchart` 返回任务流程图 JSON 和 Mermaid 文本。
- `GET /v1/reports/{report_id}/flowchart?version=N` 返回指定报告版本对应的流程图。
- UI 增加“流程图”页签，显示 Mermaid 源码和结构化节点；首版不要求浏览器端图片渲染。

## 验收标准

1. 相同任务输入产生稳定的节点和边顺序。
2. 三个研究产品显示为并行分支；trace 中有补查时显示补查边或节点。
3. `failed`、`partial`、`input_required`、`interrupted` 等状态不会被渲染成成功。
4. 流程图不包含模型思维链、密钥、完整请求或原始异常文本。
5. 不存在的任务和报告版本返回 404；流程图查询不消耗模型或搜索预算。
6. fixture 运行可完成 API 和核心构建器测试；真实模型和 ComfyUI 不作为首版通过条件。
